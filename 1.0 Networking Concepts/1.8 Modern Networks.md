# 1.8 - Modern Networks  
Comptia objective: Summarize evolving use cases for modern network environments.

## SDN/SD-WAN
- SDN (Software Defined Networking)  
  Enabling network management through software applications
- SD-WAN (Software Defined WAN)  
  A specific application of SDN applied to WAN connections used to connect enterprise networks. Including branch offices and data centers, over large geographic distances  
  Enhances business efficiency by dynamically routing traffic across the optimal path using a centralized control function. Ensuring high performance and reliability for critical applications
- Application Aware  
  SD-WAN technology intelligently identifies applications and can prioritize traffic based on business requirements. Ensuring critical applications have bandwidth and path reliability they need
- Zero Touch Provisioning  
  Network devices auto download configs from a central repository. Simplifying branch deployments
- Transport Agnostic  
  SD-WAN is flexible with the type of connectivity it uses. Allowing for cost effective and reliable internet access from different service providers
- Central Policy Management  
  Centralized management enables network admins to set policies that manage and configure all SD-WAN devices across the network from a single interface

## VXLAN
- VXLAN (Virtual Extensible LAN)  
  A network virtualization technology that enhances the scalability of large scale cloud computing environments  
  Extends layer 2 segments over an underlying layer 3 network, ensuring the creation of a large number of virtualized LANs 
- DCI (Data Center Interconnect)  
  XVLANs are particularly effective for DCI by enabling the stretching of layer 2 networks across geographically dispersed data centers  
  This capability allows for seamless mobility of VMs between data centers without changing underlying network connections
- Layer 2 Encapsulation  
  VXLAN uses Layer 2 Encapsulation to encapture ethernet frames within UDP packets  
  Allows VXLANs to create a logical network for VMs across different physical networks, providing scalability beyond the traditional 4096 VLAN limit

## Zero Trust Architecture
- Zero Trust  
  A security model based on "never trust, always verify"  
  Requires strict identity verification for every person and device trying to access resources on a private network  
  Minimizes potential attack vectors by treating all users as potential threats and enforcing strict access controls and not assuming trust based on network location
- Policy-based Authentication  
  In a zero trust framework, policy based authentication requires all users, internal and external, to be authenticated and continuously validated for security config and posture before being granted access to data and applications  
  May include MFA, biometrics, and behavioral analytics to ensure only legit users gain access
- Authorization in Zero Trust Architecture  
  Authorization in zero trust is dynamic and strictly enforced before access is allowed  
  This process is context aware, taking into account the users identity, location, device health, service or workload, data classification, and anomalies  
  Access to resources is granted on a per-session basis, ensuring that access rights of users are constantly evaluated and adjusted based on the latest security intelligence and context
- Least Privilege Access  
  A security model that requires that users, systems, and programs are granted only the minimum level of access and permissions needed to perform necessary tasks  
  Minimizes potential damage from accidental or malicious actions by limiting access rights

## SASE/SSE
- SASE/SSE  
  Combines network security functions with WAN capabilities to support the dynamic secure access needs of an organizations distributed work forces and cloud first strategies
- SASE (Secure Access Service Edge)  
  Integrates comprehensive WAN services and security functions directly into the network fabric  
  Provides secure network connectivity and access to resources regardless of location
- SSE (Security Service Edge)  
  Focuses more on the security aspects, centralizing various security services like secure web gateways, cloud access security brokers, and zero trust network access

## IaC
- IaC (Infrastructure as Code)  
  A key practice in cloud computing and DevOPs that involves managing and provisioning computing infrastructure through machine readable definition/config files, rather than physical hardware configs  
  Enables IT infrastructure to be automatically managed, monitored, and provisioned through code. Improving consistency, efficiency, and reducing manual errors
- Automation in IaC  
  Reduces human error and increases efficiency in deploying infrastructure  
- Paybooks, Templates, and Reusable Tasks  
  Defines and orchestrates the steps needed for infrastructure setup, modification, and management
- Config Drift and Compliance  
  Environment's current config deviates from its intended state due to manual changes/updates  
  IaC also aids in maintaining compliance with defined standards and policies by automating configs and deployments
- Upgrades  
  Upgrades to infrastructure can be managed systematically through code revisions  
  Ensures that upgrades are less disruptive and all changes are version controlled and reversible
- Dynamic Inventories  
  Infrastructure resources are automatically discovered and managed based on real time data  
  Essential for managing environments that need to adjust quickly to changing demands or configs
### IaC Source Control
- Source Control
  Provides a system for tracking changes, collaborating, and maintaining the integrity of code that defines infrastructure
- Version Control
  Keeps track of modifications to code in a DB
- Central Repository
  Acts as the single source of truth for all code changes, allowing teams to collaborate effectively, accessing and updating code securely and efficiently
- Conflict Identification
  Source control systems automatically detect conflicts when multiple team members make changes to the same part of code
  Crucial for preventing overwrites and ensuring that all changes are reconciled before code is merged
- Branching
  A feature of source control that allows devs to diverge from the main branch of development and continue to work independently without affecting others' work
